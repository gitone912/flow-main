# 입력 내용 (각 칸에 그대로 복사해서 붙여넣기)

> 1차 제안서(SkillRelay)에서 바뀐 점: 서비스 이름을 **Flow**로 통일, 주제와 관련 없는 자살 사망 통계 삭제, 대상을 소상공인 · 소규모 IT 사업장으로 명확히, 데이터 출처 · AI 정확도 · 기술 구성 · 개인정보 원칙 추가 (1차 심사 의견 반영).

## Project Name (프로젝트 명칭)

Flow

## Optional Topics (선택 주제)

TRACK 2 · 소상공인 경영 문제 해결

## Problems you want to solve (해결하고 싶은 문제)

서울의 소규모 IT 사업장에는 인사팀도 PM도 없어서, 급한 일이 들어오면 대표나 팀장이 혼자 기억에 의존해 담당자를 정합니다. 한 직원이 여러 프로젝트에 참여하고 프로젝트 업무 · 회의 · 코드 리뷰 · 고객 지원 · 당직 일정이 여러 도구에 흩어져 있어, 누가 지금 그 기술과 실제 시간을 가졌는지 알기 어렵습니다. 그래서 긴급 업무는 먼저 답하거나 익숙한 몇 명에게 반복해서 몰립니다. 그 사람이 한 시간밖에 여유가 없어도요. 기존 마감이 밀리고 초과근무가 쌓이며, 누가 최근 30일 동안 긴급 업무를 몇 건 맡았는지는 어디에도 기록되지 않습니다. 작은 회사에서 이는 곧 경영 문제입니다. 마감 지연은 고객 이탈로, 핵심 인력의 과로는 이직과 채용 비용으로 이어집니다. 특히 상시 5명 미만 사업장에는 근로기준법의 주 40시간 · 연장근로 한도가 적용되지 않아, 법이 대신 막아 주는 장치도 없습니다.

## Solution Ideas (해결 아이디어)

Flow는 긴급 업무가 도착한 순간, 후보마다 실제로 남은 업무 시간과 최근 긴급 업무 부담을 즉시 비교해 대표(팀장)가 근거를 보고 배정하게 돕는 서비스입니다. 기존 도구가 “누가 바쁜가”를 보여준다면, Flow는 “이 일을 마감 전에 무리 없이 끝낼 사람은 누구인가”에 답합니다.

① 업무 요청 파악: 메신저 요청 한 줄을 붙여넣으면 AI가 필요한 기술, 예상 소요 시간, 마감, 선행 조건을 초안으로 정리하고, 모호한 범위나 테스트 환경 권한은 배정 전에 질문으로 확인합니다. AI 예상 시간은 유사한 완료 업무의 실제 소요 시간과 비교해 보정합니다(예: 4시간 → 4시간 15분).

② 실제 가용 시간 계산(규칙 기반): 여러 프로젝트 업무 · 회의 · 코드 리뷰 · 고객 지원 · 당직을 한 일정에 모아, 근로시간 · 휴게 기준, 집중 작업에 필요한 연속 시간, 돌발 요청 대비 예비 시간을 코드 규칙으로 계산합니다. 같은 입력이면 항상 같은 결과가 나옵니다.

③ 후보 비교와 승인: 후보마다 경험 → 하루 일정 위 실제 가용 시간(연속 시간과 조각 시간 구분) → 배정 시 영향(기존 마감, 주 40 · 52시간)을 같은 순서로 보여줍니다. 조건이 비슷하면 최근 긴급 업무를 덜 맡은 직원이 앞섭니다. 선택하면 새 업무가 들어갈 위치를 미리 보여주고, 승인 직전 영향받는 기존 마감을 요약하며, 대표가 승인해야만 공용 일정에 예약됩니다. 모두 바쁘면 업무 분할, 마감 조정, 기존 업무 이동, 단계별 인계를 즉시 다시 계산해 제안합니다.

예시: 고객사 데모 전 대시보드 오류 수정(최대 4시간). 기존 담당자는 배포 준비와 코드 리뷰로 1시간만 남고, Flow는 같은 기술을 갖추고 5시간이 남은 동료를 추천합니다. 대표는 이유와 배정 후 남는 1시간을 확인하고 승인합니다.

④ 직원 참여와 개인정보: 직원은 Flow가 가진 자기 정보 전체를 열람하고, 빠진 업무 · 예상 시간 · 스킬 · 근무 시간을 추천 바로 옆에서 직접 정정하며, 배정 이유를 보고 재검토를 요청합니다. 업무량 데이터는 업무 배분에만 쓰고 인사 평가에는 쓰지 않습니다. 개인정보 보호법의 최소 수집 원칙, 자동화된 결정에 대한 설명 · 거부권(제37조의2), 인공지능 기본법의 사람 개입 원칙을 설계에 반영했습니다. AI는 초안과 설명만 하고, 직원 이름과 기록은 AI로 보내지 않습니다.

⑤ 팀 단위 개선과 효과 검증: 대시보드는 순위표 대신 긴급 업무가 반복되는 사람, 겹치는 일정, 조각난 일정을 보여주고, 한 사람만 가진 기술은 페어링을 제안합니다. 같은 요청을 “기존 담당자 우선”으로 배정했을 때와 Flow 추천을 시뮬레이션으로 비교해, 예정 근무시간 초과 배정 비율과 과부하 반복 횟수를 확인합니다. 시범 운영에서는 실제 초과근무 시간과 익명 설문으로 효과를 검증합니다.

데이터는 직원이 새로 입력하지 않고 Google Calendar · Outlook, Jira · GitHub 같은 기존 도구에서 가져오는 구조이며, 현재는 제공된 직원 CSV 1,000명과 합성 일정 데이터, CSV 가져오기로 시연합니다. React · TypeScript 웹 앱(Vercel), Hono API 서버, Groq LLM(openai/gpt-oss-120b), Supabase(Postgres)로 구현했고, AI 호출이 실패해도 규칙 기반 파서로 전체 흐름이 동작합니다.
